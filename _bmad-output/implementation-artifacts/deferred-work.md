## Deferred from: code review of spec-1-5-semantic-design-token-system-and-typography (2026-10-28)

- **DESIGN.md must add authoritative Dark Mode `-border` values before Story 1.6.** DESIGN.md's "Dark Mode — Semantic Token Map" table omits dark rows for `--color-success-border`, `--color-warning-border`, `--color-danger-border`, and `--color-info-border`. `tokens.css` carries the Light values forward in `.dark` as a documented gap-fill (AD-10 forbids inventing colors, so no new dark hues were derived). No component consumes these borders until Story 1.6, so nothing is visually wrong today. The fix edits the design-authority doc (DESIGN.md), not code — out of code-review scope. Added a regression test (`carries the four status -border tokens forward in .dark`) that pins the current gap-fill so a silent change is caught; when DESIGN.md gains authoritative dark `-border` values, update `DARK_HEX` in `tokens.test.ts` to lock them.
- **Computed-style / rendered-DOM verification of utility resolution and Sinhala typography is routed to Playwright (Story 9.3).** The Light/Dark acceptance criteria are phrased against `getComputedStyle` of `bg-surface text-brand border-border`, and the Sinhala rules against a rendered `html[lang="si"]` document. `tokens.test.ts` asserts the token contract and the base-layer CSS rules as text (jsdom cannot compute Tailwind `@theme` output). During this review the resolution was verified empirically by building the frontend and inspecting the compiled CSS — `.bg-surface{background-color:var(--color-surface)}`, `.text-brand{color:var(--color-brand)}`, `.border-border{border-color:var(--color-border)}` all generate, and `.dark` reassigns the variables — so AC #1/#2 hold. A browser-rendered computed-style assertion belongs in the Story 9.3 E2E suite (en/si × light/dark), not in this foundation story.
- **Line-height and component-dimension tokens are not exposed as Tailwind utilities.** `--leading-base/-sinhala/-heading` and `--button-height`, `--input-height`, `--sidebar-width`, `--topbar-height`, `--mobile-nav-height`, `--touch-target-min` are declared in `tokens.css` but not mapped in the `@theme` block, so `leading-*` and dimension utilities don't generate (confirmed: `.leading-sinhala` is absent from the compiled CSS). Line-height is applied correctly via base-layer rules; the component dimensions are consumed by Story 1.6 components. Expose whichever of these Story 1.6 needs as utilities (or reference the vars directly) when building the components — deferred, not a 1.5 defect.
- **Focus-ring and elevation/box-shadow tokens are absent.** DESIGN.md defines `focus-ring: "3px solid #3E3A98"`, a focus glow `0 0 0 3px rgba(62,58,152,.15)`, and an elevated box-shadow `0 4px 20px rgba(62,58,152,.10)` (dark: `rgba(0,0,0,.3)`). These are component-level concerns (Story 1.6 Button/Input/Card/Modal) and `focus-ring` embeds a raw hex, so they were correctly left out of the token-foundation story. Add them as tokens (or component styles) in Story 1.6 so components don't hard-code shadow/ring values.
- **Heading line-height has no Sinhala counterpart.** `--leading-heading: 1.2` is correct for English, but DESIGN.md requires `1.4` minimum for Sinhala headings. No heading element or heading rule exists in Story 1.5 (headings arrive with components in 1.6), so this is not a 1.5 defect. When 1.6 introduces heading styles, add an `html[lang='si']` heading line-height ≥1.4 rule.

## Deferred from: code review of spec-1-7-react-app-shell-routing-and-themecontext (2026-10-28)

- **Sinhala wording for `topbar.language.switchToEnglish` is still the English string.** `locales/si/common.json` carries `"switchToEnglish": "Switch to English"`. en/si key parity holds (validate-i18n green), but the Sinhala label is untranslated. The exact Sinhala string is an Institute deliverable (EXPERIENCE.md OI-03), not UX/architecture scope. When the institute supplies the Sinhala text, update the key and the `LanguageSwitcher.test` assertion that currently pins the English string.
- **NotFound (`*`) links to the public home, not a role-aware "Go to Dashboard."** EXPERIENCE.md §404 specifies a role-appropriate dashboard button. NotFound also renders for unauthenticated visitors (no role), so a correct role-aware destination depends on the real auth/role state that Epic 2 provides. `AccessRestricted` already routes role-aware via `roleHomePath`. Revisit NotFound's destination in Epic 2 once authenticated role context is reliably available at the `*` route.
- **`AccessRestricted` renders chromeless and its heading is not focused on entry.** `ProtectedRoute` returns `<AccessRestricted/>` directly (not inside `AppLayout`), so the 403 surface has no topbar/sidebar and the route-change focus hook (which lives in `AppLayout`) never moves focus to its heading. The Story-1.7 I/O matrix only requires an access-restricted view with a link back and the target nav never rendered, which is met. When shell-nested error surfaces are standardized, mount `AccessRestricted`/`NotFound` inside the shell for the authenticated case and move focus to their `tabIndex={-1}` heading.
- **`returnUrl` needs open-redirect validation before Epic 2 consumes it.** `ProtectedRoute` encodes `location.pathname + location.search` into `?returnUrl` and `Landing` only displays it today. The real login flow (Epic 2) MUST validate the value is a local path (reject protocol-relative `//host`, absolute URLs, and non-local targets) before calling `navigate(returnUrl)`. Flagged now so Epic 2 does not blindly redirect.
- **Nav icons are raw Unicode glyphs with no font-coverage guarantee.** `nav-config.ts` uses glyphs (e.g. `⌂ ▤ ⌕ ₨ ◔ ◉ ⇪ ∑`) that may render as tofu boxes on low-to-mid-range Android browsers (the primary student device) since they are not in the self-hosted Inter/Noto subset. They are `aria-hidden` (labels carry meaning), so this is cosmetic, not an a11y break. Introduce a proper icon set (inline SVG sprite or an approved icon dependency via AD) when the dashboards are built.
- **Theme is not reconciled across tabs or live OS-preference changes.** `ThemeContext` resolves once in a lazy initializer and only updates on explicit toggle — no `storage` event listener for multi-tab sync and no `matchMedia('(prefers-color-scheme)')` change listener for users with no stored preference. Out of Story 1.7 scope; natural home is the user-preferences story (Epic 2.8 — theme/language persistence).
- **Drawer focus trap edge cases.** The Tab handler in `Drawer.tsx` only redirects focus when the active element is exactly the first or last focusable node; focus that somehow lands elsewhere is not corrected, and the drawer does not auto-close if the viewport is resized to ≥1024px while open (it becomes `lg:hidden` but stays mounted with focus trapped). Both are narrow given the drawer's nav-only content today. Harden the trap (handle "focus outside the set" and `contenteditable`/positive-tabindex) and add a `matchMedia` auto-close when drawer content grows in later epics.
- **`statusLabels` compat shim falls back `si → en → key` silently.** `buildLabels()` in `status-labels.ts` degrades a missing Sinhala status key to English (then the raw key) with no runtime signal. The CI validate-i18n parity gate prevents this today, but a dev-mode `console.warn` on fallback (mirroring StatusPill's unknown-status warn) would fail-fast if the gate were ever bypassed. Low priority; the shim is deprecated in favor of `t('status:<KEY>')`.
